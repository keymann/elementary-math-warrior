# 밸런스 시뮬레이션 결과 (Phase 7)

> 측정 도구: `npm run sim -- runs=N`  ·  최종 측정 2026-08-07, 96판(셀당 8판)

## 도구

헤드리스 시뮬레이터. 렌더 없이 고정 타임스텝만 돌려 **최대 435배속**으로 판을 진행한다.
`World` 가 DOM 에 의존하지 않아 그대로 Node 에서 실행된다.

- 퀴즈는 실제로 출제하지 않고 **정답률을 입력 변수**로 둔다. 시뮬레이터가 재는 것은 게임
  밸런스이고, 문제 자체의 품질은 어댑터 PoC 가 따로 검증한다.
- 봇에 `skill` 0~1 파라미터를 뒀다. 이전에는 조작 방식만 바꿔도 생존이 40초 ↔ 3분으로
  뒤집혀 **밸런스가 아니라 봇 실력을 재고 있었다.**

## 시뮬레이터가 잡은 결함

**3분 보스가 잡히지 않아 720초 교착.** 무기가 가장 가까운 적을 조준하는데 잡몹이 항상 더
가까워 보스에 피해가 거의 들어가지 않았다. 보스전 동안에는 타이머가 멈추므로 판이 영원히
끝나지 않는다. 실시간 플레이로는 발견하기 어려운 결함이었다.

→ 보스 우선 조준 + 중간보스 100초 제한(넘으면 보스가 물러나고 타이머 재개).

## 목표치 재검토 (결정 사항)

러버밴딩(난이도 자동 보정)은 **넣지 않기로 했다.** "모두가 같은 난이도"라는 전제를 유지한다.
대신 두 지표의 정의를 고쳤다.

- **각성 도달률**: 전체 판 → **6분 이상 생존한 판** 기준. 3분에 죽은 판은 애초에 각성을 볼
  기회가 없어 분모에 넣으면 게임이 아니라 조기 사망률을 재게 된다. 재정의 후 41.7% → 57.4%.
- **미숙련 첫 사망**: 목표 구간 판정을 **파일럿까지 보류**. 아래 한계 참고.

## (기록) 두 지표가 충돌했던 이유

**각성률 70% 와 미숙련 첫 사망 4~6분은 같은 원인이다.** 미숙련(전체의 1/3)이 3분에 죽어
Lv.10 에 그치니 각성을 볼 수 없고, 따라서 각성률 상한이 약 67% 로 묶인다.

그런데 **초보를 더 살려주면 숙련 클리어율이 함께 오른다.** 숙련은 이미 84.4%, 전체
클리어율은 상한(50%)에 근접해 여유가 없다. 한쪽을 만족시키는 순간 다른 쪽이 깨진다.

선택지는 둘이다.

1. **난이도 자동 보정(러버밴딩)** — 레벨·생존 상황이 나쁘면 스폰·피해를 완만하게, 잘 풀리면
   조인다. 교육용 게임의 표준 해법이고 두 지표를 동시에 만족시킬 수 있다. 다만 "모두가 같은
   난이도"라는 전제를 바꾸는 설계 결정이다.
2. **목표치 재검토** — 미숙련 봇(skill 0.45)이 실제 초보보다 가혹할 수 있다.

## ⚠️ 이 수치의 한계

**봇 프로필은 사람 데이터로 보정되지 않았다.** skill 0.45 는 이동 방향 오차 ±99° 를 뜻하는
임의값이고, 실제 초등학생의 조작 수준과 대응된다는 근거가 없다.

교실 파일럿에서 **실제 생존 시간 분포**를 받아 프로필을 역산한 뒤 위 지표를 다시 재야 한다.
그 전까지 이 표는 "조정 전후 비교"로는 쓸 수 있지만 "실제 학생의 클리어율"로 읽으면 안 된다.
보정되지 않은 측정 도구에 게임을 과적합시키지 않으려고 튜닝을 여기서 멈췄다.
